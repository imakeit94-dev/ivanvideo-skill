# 真实产品证据与展示

涉及真实软件功能宣传、版本更新或功能演示时读取；普通解释动画不必建立产品证据表。方法参考 guizang-product-video-skill 的受控组件与证据实践，以下是 IvanVideo 自身的流程约定。

## 从功能到镜头

确认产品名、版本/构建、平台、功能状态和可访问的实际入口。将每个宣传主张对应到用户提供的可验证资料、源码入口或真实操作。数据示例、功能规划和当前已实现功能分别标明；不把模拟界面当成实测结果。

展示方式按可用材料选择：

- **真实录屏/截图**：记录版本、操作步骤和捕获范围。静态截图只能证明当时可见状态，不能独自证明完整交互已成功。
- **原组件运行**：使用对应业务组件、原样式和必要上下文；固定且脱敏的数据与状态驱动留在视频工程。列明实际使用的组件，不把引用一个基础按钮说成复用了整个功能。
- **说明性重建**：无法运行原软件而采用示意时，写清依据和局限，不能冒充运行中的原产品。是否适合宣传目的需遵循用户要求。

动画外框、聚焦和缩放可以服务叙事；不得因此换掉软件本体的真实状态、正式图标或品牌颜色。原生桌面程序不默认能作为 React 组件导入。适配代码放在视频项目，修改原产品需另有任务授权。

## 最小证据记录

在工程 `references/product-evidence.json` 中记录数组；这是制作与审片材料，机器不会据此自动宣布功能真实：

```json
[
  {
    "shot_id":"S02",
    "claim":"支持把当前列表导出为 CSV",
    "product":"实际产品名",
    "version":"实际版本或待确认",
    "platform":"实际平台",
    "display_mode":"real_capture",
    "feature_entry":"实际页面、菜单或源码位置",
    "sources":["用户提供的功能说明或可访问来源"],
    "captures":["assets/export-capture.mp4"],
    "state_driver":"捕获的操作步骤或适配文件路径",
    "data_kind":"demo",
    "limitations":["待完成的核对项"],
    "review_status":"pending"
  }
]
```

display_mode 可用 real_capture、original_component、illustrative_reconstruction。只有实际审阅后才更新 review_status 并写明核对人/时间。版本未知就保留未知，不能填一个猜测值；虚构 UI 的测试样片明确标为测试，不能代替真实产品验收。

审片时对照来源、操作/导入路径及实际导出帧，核对文字、布局、图标、状态和功能结果。素材、示例数据及源码涉及敏感内容时使用已授权的脱敏版本。记录和截图属于具体项目，不随公共 Skill 自动上传。

网页可用 [software-capture.md](software-capture.md) 的工具保存实际步骤、断言、截图及录屏；在分镜中绑定捕获报告能检查引用一致性，但不会自动把功能真实性审阅改为通过。本机工具测试仅证明采集/验证流程可运行，不能替代用户产品验收。
